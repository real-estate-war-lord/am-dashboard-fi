# V2 — Colour rule for signed indicators (owner request, 2026-09-25)

Owner: "e.g. population growth must show two levels for positive growth, e.g. above +0.5 % and 0–0.5 %, then red
for 0 to −0.5 %, etc." Today signed indicators use quantiles of |v − centre|, so the bins move every year and
zero is not visible. New rule:

1. **Signed indicators** (values can be both positive and negative: population growth, net migration,
   intermunicipal net migration, every y/y change, price and rent change, outlook change 2026→2040, crime trend,
   and any other indicator whose published values straddle 0 — list them in `src/ramp_core.js`) get a
   **diverging ramp with fixed, readable breaks centred on 0**: two green classes above zero and two red classes
   below zero, plus `no data`. Default breaks: `< −t`, `−t … 0`, `0 … +t`, `> +t`. Per-indicator `t`
   in one table in `src/ramp_core.js` (growth % / yr: 0.5; net migration per 1 000: 5; intermunicipal net
   migration per 1 000: 5; price / rent change y/y %: 2; outlook change 2026→2040 %: 5; crime trend %: 5).
   If a sixth class is needed because > 20 % of areas fall beyond ±3t, add `> +3t` / `< −3t` (darker) — decide from
   the data at build time, log it. Exactly 0 goes to the positive-low class and the legend says "0 … +0,5 %".
2. **Lower-is-better signed indicators** (crime trend): increase = red, decrease = green; the legend says so.
3. Colours: greens from the existing observed ramp; reds a muted brick red that fits the paper background
   (e.g. `#B5523B` dark, `#E3A08F` light); both pass 3:1 against each other and against `no data` grey.
   Projections (outlook change) keep purple for positive and use a muted red for negative; say so in the legend.
4. Legend: bins in value order top = highest, labelled with signed fi-FI values and the unit ("> +0,5 %",
   "0 … +0,5 %", "−0,5 … 0 %", "< −0,5 %"), a thin rule between the positive and negative bins, footer
   "fixed breaks, centred on zero". Same ramp on the main map, area-page minimap, property minimap, and the
   distribution strip dots.
5. Non-signed indicators keep the current sequential quantile ramps.
6. Tests: `tests/ramp.test.js` (break selection, zero handling, lower-is-better flip, the ±3t rule) and ui checks
   (phase V2): `#map?ind=growth` legend has 4 (or 6) bins, at least one red swatch, text "0 … +0,5 %";
   `#map?ind=crime_trend` (use the real key) legend says lower is better with red on the increase side.
7. Apply the same rule, if the code path is shared, to the Charts distribution mode. Screenshots of `#map`,
   `#map/091` and `#area/kunta/091` at 1440 and 390 must show the red/green split clearly.
